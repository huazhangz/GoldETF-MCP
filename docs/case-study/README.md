# Case study: can anything beat a random walk for gold-ETF volatility?

This revisits a course time-series project (STAT 429, Spring 2026) on the CBOE Gold ETF Volatility Index
(`GVZCLS`), redone end to end through this MCP server's tools. The original project fitted five ARIMA models
to monthly log GVZ, chose ARIMA(2,1,2) because it was the only one to pass a Ljung-Box check, and forecast
five months ahead. It ended with two open questions:

1. Why does no ARIMA model clearly beat a random walk?
2. Would a GARCH model, which captures changing volatility, fix that?

Files in this folder:

- `gvz-transcript.md` is every tool call and its key numbers, generated by `scripts/case_study.ts`.
- `gvz-results.json` is the full JSON returned by each call.
- `gvz-crosscheck.md` re-runs the backtest with statsmodels/arch (`scripts/verify_case_study.py`).

Data: FRED `GVZCLS`, daily closes averaged to months, 2008-06 to 2026-04 (n = 215, same sample as the course
project), log-transformed. Run on 2026-11-24.

## Summary

| Question | Answer from the data |
| --- | --- |
| Does any model beat the random walk out of sample? | **No, not significantly**, at 1, 3 or 6 months (143 rolling origins, Diebold-Mariano p > 0.2). |
| Which model forecasts best? | **AR(1) on the log level** (mean reversion; half-life ~6 months): RMSE 1.7% / 4.3% / 2.9% below RW. |
| How did the course model do? | **ARIMA(2,1,2) is the worst model tested**: RMSE 2.6% / 7.9% / 24.5% *above* RW. |
| Is there volatility clustering to model with GARCH? | **Not at monthly frequency** (ARCH-LM p = 0.994; GARCH alpha -> 0; BIC prefers constant variance by 9). Strong clustering exists in the **daily** data (alpha 0.14, beta 0.76). |
| Does "volatility" matter at all? | **Yes, through fat tails, not clustering.** Monthly changes have kurtosis 8.9 and skewness 1.65; the 5% largest months produce 47% of the random walk's squared error. A Student-t model raises the log predictive score from 0.50 to 0.65, the largest improvement of anything tried. |

So the hypothesis "the model can't significantly beat a random walk mainly because of volatility" is **partly
right**:

- **Right:** a handful of large, unforecastable shocks (2008, 2011, 2020, 2025-26) dominate squared-error loss.
  This makes accuracy differences statistically invisible over 143 origins. Even on synthetic AR data with a true
  13% RMSE advantage, 100 origins gave a DM p-value of only 0.09.
- **Not quite right:** it is not *conditional heteroskedasticity*. At monthly frequency there is no ARCH effect
  for a GARCH model to capture. GARCH also changes interval forecasts, not point forecasts, so it could never make
  point forecasts beat a random walk.
- **Missing piece:** the predictable part of GVZ is **mean reversion in the level**. Taking a first difference
  (d = 1) throws it away, so every ARIMA(p,1,q) is a random walk plus noise. The fitted d = 1 models say so
  themselves: their MA roots sit near 1 (0.96 for ARIMA(1,1,1), 0.90 for ARIMA(2,1,2)) and nearly cancel the
  difference. That is the textbook sign of over-differencing.

## 1. Reproducing the course results

| Course notebook | Tool call | Result |
| --- | --- | --- |
| 1.3 Monthly aggregation | `fred_get_observations` `frequency: "m"` | n = 215, 2008-06 to 2026-04 (partial months are dropped automatically) |
| 2.4 STL, strength metrics | `ts_decompose_stl` on log | F_T = 0.686, F_S = 0.030 (course: 0.689 / 0.030); seasonal peak-to-trough 0.08 vs remainder RMS 0.17 |
| 2.2 ADF/KPSS table | `ts_test_stationarity` with 5 transforms | log level: **conflicting** (ADF p = 0.012, KPSS p < 0.01); log diff: stationary |
| 2.2.1 "R gives p = 0.113" | same, `regression: "ct", adf_lags: 5` | p = 0.128. `tseries::adf.test` always includes a **trend** and uses lags = trunc((n-1)^(1/3)); the lag rule alone does not explain the difference |
| 2.3 ACF/PACF | `ts_autocorrelation` on log diff | only lag 3 is outside the band; smallest Ljung-Box p = 0.039 (lag 4) |
| 3 ARIMA candidates | `ts_fit_arima` | see section 2 |

The STL shock list matches the course narrative without manual reading of plots: the largest remainders are
2008-06/07/08 (financial crisis, negative after the spike), 2020-03/04 (Covid), and 2011-09.

## 2. Model selection: the d = 1 family is over-differenced

`ts_fit_arima` ranks candidates **within** each differencing order, because AICc values are not comparable
between models fitted to levels (d = 0) and to differences (d = 1).

| d | Best model | Notes from the tool |
| --- | --- | --- |
| 0 | **AR(1)**: mean 2.916 (GVZ about 18.5), phi = 0.895 (se 0.031) | ARMA(1,1) and AR(2) are within 0.2 AICc, but their extra terms are insignificant, so the simpler AR(1) wins |
| 1 | ARIMA(1,1,1): ar 0.84, ma -0.96 | "MA inverse root 0.959 nearly cancels the differencing: likely over-differenced (try d = 0)" |
| 1 | ARIMA(2,1,2) (course model) | ar2, ma2 and drift insignificant; MA root 0.90, same over-differencing warning |

Why the course concluded that only ARIMA(2,1,2) passed Ljung-Box: the random walk's Ljung-Box p-value dips to
0.039 at lag 4 out of 20 lags inspected. Lag 4 out of 20 is the kind of crossing expected by chance. Ljung-Box
is an adequacy check, not a selection criterion. Adding AR and MA terms until it passes produced a model whose
extra terms are insignificant and which forecasts worst out of sample.

Why the level is a sensible target: ADF rejects a unit root on log GVZ (p = 0.012) while KPSS rejects
stationarity. That conflict is typical of a persistent but mean-reverting series, and implied volatility is
the standard example. A unit-root model implies GVZ can drift anywhere; the data say it returns towards about 18
with a half-life of ln(0.5)/ln(0.895), about 6.3 months.

## 3. Volatility: where GARCH belongs

| | Monthly log changes | Daily log changes |
| --- | --- | --- |
| ARCH-LM (12 lags) | p = 0.994 | p < 1e-4 |
| GARCH(1,1)-t alpha / beta | ~0 (on the boundary) / unidentified | 0.143 / 0.762 (robust se 0.026 / 0.048) |
| GARCH vs constant variance | LR p = 0.43, BIC **+9.0** (worse) | BIC **-293** (better) |
| Tails | kurtosis 8.9, skewness 1.65 | kurtosis 10.1, skewness 0.86 |

Volatility clustering in GVZ is a daily phenomenon with a half-life of about 7 trading days. Averaging 21 days
into a month removes it, which is what temporal-aggregation theory predicts for GARCH processes (Drost & Nijman
1993). The rolling-SD chart in the course notebook showed regimes in the *level* of GVZ, not in the variance of
its shocks, which is why it looked like a case for GARCH. `ts_fit_garch` makes this decision explicit: it runs
the ARCH-LM pre-test first and compares against the same model with constant variance.

What does survive aggregation is heavy, right-skewed tails, so the distribution matters more than the variance
dynamics.

## 4. Out-of-sample evidence (`ts_backtest`)

The setup is an expanding window: the first fit uses 72 months, and the model is refit at each of 143 origins
from 2014-06 to 2026-04. Errors are on the log scale, so an error of 0.1 means about 10%.

| Model | rel RMSE h=1 | h=3 | h=6 | log score h=1 | coverage 80% / 95% (h=1) |
| --- | --- | --- | --- | --- | --- |
| Random walk (benchmark) | 1 | 1 | 1 | 0.504 | 0.88 / 0.94 |
| RW + drift | 1.004 | 1.014 | 1.030 | 0.500 | 0.88 / 0.94 |
| ARIMA(1,1,1) | 1.018 | 1.026 | 1.042 | 0.487 | 0.84 / 0.94 |
| ARIMA(2,1,2) (course) | 1.026 | 1.079 | **1.245** | 0.460 | 0.84 / 0.94 |
| **AR(1)** | **0.983** | **0.957** | **0.971** | 0.522 | 0.87 / 0.94 |
| AR(1)-t | 0.984 | 0.965 | 0.984 | **0.649** | 0.83 / 0.94 |
| AR(1)-GARCH(1,1)-t | 0.985 | 0.967 | 0.989 | 0.640 | 0.82 / 0.93 |

- No model's RMSE difference from the random walk is significant at 5% at any horizon. ARIMA(1,1,1) is
  significantly *worse* at h = 3 (p = 0.049).
- The AR(1) gain is larger after turbulent periods: at h = 6 its relative RMSE is 0.94 in turbulent regimes
  versus 1.04 in calm ones. That is where the level is far from its mean and mean reversion pays.
- Gaussian intervals cover 88% instead of 80% and 94% instead of 95%: too wide in the middle and too narrow in
  the tails, the signature of fat tails. Student-t errors fix the density forecast (log score +0.14); GARCH adds
  nothing on top.

The independent statsmodels/arch re-run in `gvz-crosscheck.md` agrees to four decimals for RW, AR(1) and AR(1)-t.

### What actually happened after the course sample

The course sample ended in April 2026 (average 30.4, a spike). The actual May to September 2026 averages were
26.0, 27.4, 25.2, 25.7 and 25.3.

| Model (fit on data to 2026-04) | 5-month log RMSE |
| --- | --- |
| Random walk | 0.163 |
| ARIMA(2,1,2) | 0.050 |
| ARIMA(1,1,1) | 0.050 |
| AR(1) | 0.053 |
| AR(1)-GARCH(1,1)-t | 0.092 |

After a spike, every mean-reverting forecast beat the random walk by a wide margin. ARIMA(2,1,2) did well here
because its near-cancelling MA root makes it behave like a mean-reverting model for a few months. One episode is
an anecdote; the 143-origin backtest above is the evidence.

## 5. What would actually improve the forecasts

These are ordered by expected value:

1. **Model the daily data and aggregate the forecasts.** Clustering and most of the information are at daily
   frequency. Candidates are a HAR model (Corsi 2009) on daily log GVZ, or AR-GARCH-t on daily data, simulated
   forward and averaged to monthly.
2. **A skewed fat-tailed distribution** (Hansen's skewed-t). Shocks are mostly upward spikes. A symmetric t
   centers the AR(1)-t model low: its long-run level is about 14.6 versus a sample median of 17.6.
3. **Exogenous drivers**: VIX (`VIXCLS`), gold returns, real rates (`DFII10`). These are all on FRED and
   reachable with the same tools.
4. **Regime-switching** mean reversion for crisis and calm states.
5. **More evaluation power**: evaluate at daily or weekly frequency, use more origins, and use a Model
   Confidence Set instead of pairwise DM tests.

## Limitations

- One series and one sample. Significance tests over 143 overlapping multi-step forecasts have limited power.
- Multi-step predictive densities for t models are approximated by a scaled t; this is exact at h = 1.
- AR(1)-t uses a conditional likelihood (as in `arch`) while ARIMA uses the exact likelihood, so their fitted
  means differ slightly.
- GVZ data are CBOE's, distributed by FRED. They are fetched at run time and not stored in this repository.
